# Contributing

Use a supported Node.js version, run `npm ci`, then `npm run check`, `npm test`, and browser tests for UI/server changes. Add tests through public CLI/MCP boundaries when those establish the behavior. Keep format-specific malformed-input tests close to their analyzer.

Preserve evidence provenance and observed/derived/inferred distinctions. Do not turn an unavailable facet into a claim of absence. Target execution belongs to explicit upstream engine operations; workspace inspection must stay static. New format support must document real coverage and resource bounds.

Use Conventional Commit subjects. Describe the resulting behavior, relevant checks and unverified provider scope in pull requests. Avoid changing the pinned engine without reading its release changes and rerunning the real bridge test. Never commit captured private targets, credentials, node_modules or local snapshot stores.
